# Единая туристическая платформа Узбекистана — Архитектура

> Позиционирование: **«Узбекистан без гида — ваш персональный гид всегда с вами»**

---

## 1. Стратегия реализации

Реализация идёт тремя волнами. Веб-платформа делается первой — она же становится
источником контента и API для мобильных приложений.

| Волна | Что | Технологии | Оценка |
|---|---|---|---|
| **1. Веб-платформа (эта сессия)** | PWA для туриста + админ-панель + API + БД | Next.js 15, TypeScript, SQLite | 1–2 мес |
| **2. Наполнение** | 300 объектов, 4 города, аудиогиды на 3 языках, печать QR | Админ-панель, студия звукозаписи | 2–3 мес |
| **3. Мобильные приложения** | iOS + Android поверх того же API | Capacitor (обёртка PWA), далее нативный Flutter при росте | 2–4 мес |

**Почему сначала веб/PWA:** одна кодовая база даёт и приложение туристу
(открывается по ссылке, ставится на домашний экран, работает офлайн, имеет доступ
к камере для QR и к GPS), и админку, и API. Проверка гипотезы без ревью в App Store
и Google Play. Мобильные приложения потом переиспользуют 100% API.

## 2. Технологический стек

```
+--------------------------------------------------------------+
|  КЛИЕНТЫ                                                     |
|  +----------------+  +----------------+  +----------------+  |
|  | PWA туриста    |  | Админ-панель   |  | Моб. прилож.   |  |
|  | (телефон)      |  | (десктоп)      |  | (волна 3)      |  |
|  +-------+--------+  +-------+--------+  +-------+--------+  |
+----------|-------------------|-------------------|-----------+
           |        REST/JSON  |                   |
+----------+-------------------+-------------------+-----------+
|  API  (Next.js Route Handlers, /api/*)                       |
|  cities - pois - tours - planner - assistant - scan - stats  |
+--------------------------------------------------------------+
|  ДОМЕННЫЙ СЛОЙ                                               |
|  planner (алгоритм маршрута) - i18n - geo - analytics        |
+--------------------------------------------------------------+
|  ХРАНИЛИЩЕ                                                   |
|  SQLite (dev)  ->  PostgreSQL + PostGIS (prod)               |
|  Медиа: /public/media (dev)  ->  S3-совместимое + CDN (prod) |
+--------------------------------------------------------------+
```

| Слой | Сейчас (MVP) | В продакшене |
|---|---|---|
| Фронтенд | Next.js 15 App Router, React 19, Tailwind 4 | то же |
| Карта | Leaflet + OpenStreetMap | Leaflet + собственные векторные тайлы (офлайн) |
| БД | `node:sqlite` — встроен в Node 24, без нативных сборок | PostgreSQL 16 + PostGIS |
| Медиа | `/public/media` | S3 / MinIO + CDN |
| Аудио | HTML `<audio>`, файлы mp3 | HLS-стриминг + офлайн-кэш |
| QR | `html5-qrcode` (камера), `qrcode` (генерация) | то же |
| Офлайн | Service Worker + Cache API | + предзагружаемые пакеты городов |
| AI-ассистент | детерминированный планировщик + слой LLM | Claude API + RAG по базе объектов |
| Аналитика | таблица `events` | ClickHouse при росте |

**Принцип:** никакого вендор-лока на этапе MVP. Переезд SQLite → PostgreSQL
затрагивает только `src/lib/db.ts`.

## 3. Схема базы данных

```
cities --+-- pois -----+-- poi_translations
         |             +-- poi_media
         |             +-- poi_audio       (язык -> mp3 + длительность)
         |             +-- qr_codes
         |
         +-- museums --+-- exhibits --+-- exhibit_translations
         |                            +-- exhibit_audio
         |                            +-- qr_codes
         |
         +-- tours ------- tour_stops ---- pois

users ---+-- favorites  ---- pois
         +-- visits     ---- pois      (штампы Travel Passport)
         +-- user_routes

events   (обезличенная аналитика)
```

### Ключевые таблицы

**`cities`** — регион или город: `id, slug, lat, lon, zoom, cover, is_active`
плюс переводы названия и описания в `city_translations`.

**`pois`** (Points of Interest) — единая сущность для всех 13 типов меток из п. 2.1 ТЗ:

```
id, city_id, slug, category, lat, lon,
price_uzs, is_free, opening_hours (JSON), avg_visit_min,
rating, popularity, cover, phone, website, is_active
```

`category ∈ { landmark, museum, religious, nature, restaurant, cafe, hotel,
bazaar, craft, toilet, station, airport, transport }` — ровно список разделов 2.1.
Один тип сущности = один слой карты = один фильтр. Добавление новой категории
не требует новой таблицы.

**`poi_translations`** — `poi_id, lang, name, short_desc, full_story`.
10 языков из п. 6. Отсутствие перевода → фолбэк на `en` → на `ru`.

**`poi_audio`** — `poi_id, lang, url, duration_sec, narrator`.
Аудиогид — отдельная запись на каждый язык. Профессиональная озвучка
загружается через админку.

**`qr_codes`** — `code (уникальный), target_type ('poi' | 'exhibit'), target_id, scans`.
QR ведёт на `/s/<code>`, а не напрямую на объект: код можно перепривязать, не
перепечатывая табличку, и он даёт статистику сканирований (п. 17).

**`exhibits`** — экспонат музея (п. 7): `museum_id, number, period, origin, cover`
плюс переводы и аудио. `number` — тот самый «Экспонат №125» на табличке.

**`tours`** — готовые маршруты (п. 10) и авто-сгенерированные.
`tours.kind ∈ { curated, generated, user }`; `tour_stops` — упорядоченные остановки
с `arrive_min` и `stay_min`.

**`events`** — обезличенная аналитика (п. 17): `type, city_id, poi_id, lang, ts,
session_hash`. Без персональных данных — только хэш сессии.

Полный DDL — в `src/lib/db.ts`, функция `migrate()`.

## 4. Алгоритм построения маршрута (п. 3)

Вход: город, доступное время (мин), интересы (категории), бюджет, способ передвижения.

```
1. Отбор кандидатов
   pois where city = X and category in interests and is_active
   score = 0.45*rating_norm + 0.35*popularity + 0.20*interest_match
   отсев по бюджету: сумма price_uzs <= budget

2. Жадная маршрутизация с учётом времени
   старт = позиция туриста (GPS) либо центр города
   пока остаётся время:
       для каждого кандидата: cost = travel_time + stay_time
       travel_time = haversine(текущая, кандидат) / скорость(режим)
       выбрать кандидата с максимальным score / cost
       проверить расписание: объект открыт в момент прибытия?
       добавить в маршрут, вычесть время

3. Улучшение 2-opt
   переставляем пары остановок, пока сокращается общая длина

4. Вставка приёмов пищи
   если маршрут пересекает 12:00-14:00 или 18:00-20:00 —
   вставляем ближайший restaurant/cafe подходящего бюджета
```

Скорости: пешком 4,2 км/ч с поправкой 1,3 на извилистость улиц; такси 18 км/ч
в городе; автомобиль 25 км/ч.

Реализация — `src/lib/planner.ts`. Детерминированный, работает офлайн, без внешних API.

**AI-ассистент (п. 4)** — надстройка над планировщиком: разбирает фразу на
естественном языке («У меня 4 часа в Бухаре, люблю историю и хочу попробовать плов»)
в параметры планировщика, затем формулирует ответ текстом. Сам маршрут всегда
считает детерминированный алгоритм — LLM не выдумывает объекты, часы работы и цены.
Без ключа API ассистент работает на разборе по ключевым словам (так и работает MVP).

## 5. QR-аудиогид (п. 5, 7)

```
Табличка на объекте            Приложение
+----------------+
|   # ## #  ###  |   скан      GET /s/REG-01
|   ## #  # #    | ---------->  1. найти qr_codes.code
|   # ## ### #   |              2. записать событие scan (аналитика)
|    REG-01      |              3. redirect -> /poi/<slug>?lang=<выбранный>
+----------------+
```

Формат кода — короткий человекочитаемый ID (`REG-01`), URL `https://<домен>/s/REG-01`.
Работает и без установленного приложения: открывается в браузере телефона.
Админка генерирует PNG для печати с подписью объекта.

## 6. GPS-аудиогид (п. 8)

Клиент раз в 20 секунд берёт позицию (`watchPosition`), считает расстояние до
объектов загруженного города — данные уже в кэше, сервер не нужен.
При входе в радиус 150 м, если объект не показывался последние 2 часа, всплывает
карточка: «Вы рядом с Гур-Эмиром. Послушать историю?».
В PWA работает при открытом приложении; фоновый режим — задача волны 3.

## 7. Офлайн (п. 11)

Пакет города — JSON с объектами и переводами плюс тайлы карты, аудио, фото.
Service Worker кэширует по стратегиям:

- оболочка приложения — cache-first;
- ответы API — stale-while-revalidate;
- медиа города — предзагрузка по кнопке «Скачать Самарканд» (≈80–150 МБ на город).

## 9. Что требует не-технических решений

1. **Контент.** Тексты должны проверить историки. Демо-контент в `data/seed.json`
   написан по общедоступным сведениям и помечен как черновик; перед публикацией
   обязательна вычитка специалистом.
2. **Размещение QR.** Нужны договорённости с Агентством культурного наследия
   и дирекциями музеев.
3. **Озвучка.** 300 объектов × 3 мин × 10 языков ≈ 150 часов студийной записи.
   На старте: 3 языка × 100 приоритетных объектов ≈ 15 часов.
4. **Лицензии на фото.** Только собственная съёмка или CC-лицензии с указанием
   автора; поле `poi_media.license` обязательно к заполнению.
5. **Персональные данные.** Аналитика обезличена by design, но при запуске
   регистрации потребуется политика конфиденциальности и учёт закона РУз
   «О персональных данных» — включая локализацию хранения на территории Узбекистана.
