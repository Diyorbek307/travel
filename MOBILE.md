# Мобильное приложение

Коротко: **приложение уже работает как мобильное на Android и на iPhone** —
устанавливается на домашний экран, запускается без адресной строки, имеет
свою иконку и держит данные общими со всеми устройствами. Отдельной сборки
для этого не нужно. Ниже — как это устроено, как установить и что
дополнительно требуется, чтобы попасть в App Store и Google Play.

## Как синхронизируются данные

Синхронизация не требует отдельной работы: телефон, планшет и настольный
браузер — это один и тот же клиент к одному серверу.

```
iPhone ─┐
Android ─┼──► https://uzbekistan-travel.onrender.com ──► Postgres
Браузер ─┘        (/api/auth, /api/bookings, …)
```

Учётная запись, брони, отзывы и переписка с поддержкой лежат в базе на
сервере, а не на устройстве. Вошёл на телефоне — те же брони видны в
браузере, и наоборот. Проверить, что база подключена, можно запросом
`GET /api/health`: в ответе должно быть `"persists": true`.

Что хранится на самом устройстве — только выбранный язык и кэш оболочки
для офлайна (service worker, `public/sw.js`).

## Установка на телефон

Ничего скачивать не нужно — приложение ставится прямо из браузера.

**Android (Chrome).** Открыть сайт → меню «⋮» → «Установить приложение»
(или всплывающее предложение внизу). Появится иконка на рабочем столе,
запуск — во весь экран, без адресной строки.

**iPhone (обязательно Safari).** Открыть сайт → кнопка «Поделиться» →
«На экран "Домой"». В Chrome на iOS этого пункта нет — Apple разрешает
установку только через Safari.

После установки приложение умеет: работать без сети на ранее открытых
экранах, показывать свою иконку, запускаться в полный экран с учётом
чёлки и полосы жеста, открываться сразу на нужной вкладке по долгому
нажатию на значок (ярлыки «Карта» и «Аудио»).

## Иконки

Все растровые иконки собираются из двух SVG-исходников одной командой:

```bash
npm run icons
```

Исходники — `public/icons/icon.svg` (основная) и `maskable.svg` (для
адаптивных иконок Android). Скрипт `scripts/generate-icons.mjs` делает из
них PNG всех нужных размеров, включая `apple-touch-icon.png` без
прозрачности — iOS не понимает альфа-канал и залил бы углы чёрным.

**При смене логотипа** достаточно заменить два SVG и выполнить
`npm run icons` — остальное обновится само.

## Приложение в App Store и Google Play

Установка из браузера закрывает почти всё, но не даёт присутствия в
магазинах. Чтобы туда попасть, веб-приложение заворачивают в нативную
оболочку — обычно [Capacitor](https://capacitorjs.com): он показывает тот
же сайт внутри настоящего приложения, поэтому переписывать код не нужно и
синхронизация данных остаётся прежней.

Что для этого нужно сверх текущего проекта — честный список:

| Требуется | Android | iPhone |
|---|---|---|
| Операционная система для сборки | любая, в т.ч. Windows | **только macOS** |
| Инструменты | JDK 17+, Android Studio (Android SDK) | Xcode |
| Аккаунт разработчика | Google Play, $25 единоразово | Apple Developer, $99 в год |
| Проверка магазином | часы–дни | дни |

Два ограничения стоит знать заранее:

1. **Собрать приложение для iPhone на Windows невозможно.** Это требование
   Apple, а не проекта: подпись и сборка `.ipa` выполняются только на
   macOS. Варианты — компьютер Mac, аренда облачного Mac (MacinCloud,
   Codemagic, Ionic Appflow) или человек с Mac в команде.
2. **Текущая машина к сборке Android тоже не готова**: установлена Java 8,
   а нужна 17 или новее, и не установлен Android SDK.

Порядок действий, когда инструменты появятся:

```bash
npm install @capacitor/core @capacitor/cli @capacitor/android @capacitor/ios
npx cap init UzUp uz.uzup.app --web-dir=public
npx cap add android        # создаст папку android/
npx cap add ios            # только на macOS
npx cap open android       # дальше сборка в Android Studio
```

В `capacitor.config.ts` оболочку направляют на живой сайт — тогда
содержимое обновляется без перевыпуска приложения в магазине:

```ts
const config = {
  appId: "uz.uzup.app",
  appName: "UzUp",
  webDir: "public",
  server: { url: "https://uzbekistan-travel.onrender.com", cleartext: false },
};
```

Отдельно потребуется разрешить в нативных манифестах камеру (QR-сканер) и
геолокацию (карта и маршруты) — в вебе их уже спрашивает браузер.

## Что проверять после изменений

- `npm run build` — сборка проходит;
- `npm test` — тесты зелёные;
- макет на ширине 360 и 390 пикселей (типовые Android и iPhone);
- нижняя панель не перекрыта полосой жеста на iPhone;
- `GET /api/health` отвечает `"persists": true`.
