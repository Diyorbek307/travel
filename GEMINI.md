# Контекст проекта для помощника

Единая туристическая платформа Узбекистана. Веб-приложение на Next.js,
работает как PWA. Позиционирование из ТЗ: «Узбекистан без гида — ваш
персональный гид всегда с вами».

**Сначала прочитай [HANDOFF.md](HANDOFF.md).** Там состояние проекта,
известные ограничения с причинами и раздел «чего делать не нужно».
Архитектура и обоснование решений — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Команды

```bash
npm run dev      # разработка
npm test         # 68 проверок, база наполняется сама
npm run build    # сборка как на хостинге
npm run seed     # пересоздать базу из scripts/content
```

**Перед коммитом всегда:** `npm test && npm run build`. Тесты — главная
страховка проекта, они уже поймали ошибку, которую человек не заметил.

## Стек

Next.js 15 (App Router), React 19, TypeScript, Tailwind v4.
База — `node:sqlite`, встроенный в Node 24, без нативной сборки.
Карты — Leaflet, трёхмерная сцена — three.js + @react-three/fiber.
Языковая модель — Anthropic SDK, ключ в `ANTHROPIC_API_KEY`.

## Как здесь принято писать

**Язык интерфейса и комментариев — русский.** Приложение трёхъязычное
(ru/uz/en), тексты интерфейса живут только в `src/lib/i18n.ts`, в разметке
их быть не должно.

**Комментарии объясняют «почему», а не «что».** Строчка `// увеличиваем
счётчик` не нужна. Строчка про то, почему граница слова задана просмотром
по буквам, а не через `\b`, — нужна: без неё следующий человек вернёт
как было и сломает разбор кириллицы.

**Сообщения коммитов — рассказ о причине.** Что изменилось, видно в диффе.
В сообщении объясняется, зачем и какой размен выбран. Посмотри
`git log` — там есть образцы.

**Цвета и размеры — через переменные** из `src/app/globals.css`. Зашитых
`#hex` в компонентах быть не должно, кроме случаев с объяснением рядом.

**Контраст проверяется, а не угадывается.** Мелкий текст — не ниже 4.5:1.

## Границы, которые нельзя переходить

Это не стиль, а решения, от которых зависит доверие к платформе.

**Не давать модели сочинять факты.** Цены, часы работы, координаты и
маршруты берутся только из инструментов, читающих базу (`src/lib/ai.ts`).
Модель, выдумавшая стоимость билета, отправит туриста к запертой двери.

**Не подставлять фотографии объектам, у которых их нет.** У 54 объектов
из 108 есть настоящие снимки с Викисклада, у остальных — орнаментная
плашка. Пустая плашка честнее подмены.

**Не заменять планировщик языковой моделью.** `src/lib/planner.ts`
детерминирован и покрыт тестами. Модель лишь решает, когда его позвать.

**Не убирать откат помощника на разбор по правилам.** Офлайн-режим из ТЗ
требует, чтобы он отвечал без интернета и без ключа.

**Атрибуция обязательна.** Фотографии под CC BY и CC BY-SA показываются
только с автором и лицензией. Данные карт — Natural Earth и SRTM,
public domain.

## Где что лежит

```
src/app/          экраны и маршруты API
src/components/   компоненты интерфейса
src/lib/          вся логика: planner, assistant, ai, db, geo, weather
src/data/         подготовленные геоданные (границы, вода, контекст)
scripts/content/  исходный контент по городам, отсюда наполняется база
scripts/geo/      сборщики геоданных и рельефа
scripts/media/    сборщик фотографий с Викисклада
tests/            проверки логики; интерфейс намеренно не покрыт
public/relief/    карты высот и раскраски рельефа
public/photos/    снимки объектов
```

## Проверять глазами, а не на слово

Трёхмерную сцену и вёрстку можно снять headless-браузером — так уже
поймано несколько ошибок, невидимых в коде:

```bash
chrome --headless=new --hide-scrollbars --enable-unsafe-swiftshader \
  --use-gl=angle --use-angle=swiftshader --window-size=1000,760 \
  --screenshot=out.png --virtual-time-budget=25000 http://localhost:3000/explore
```

Окно уже 500 пикселей Chrome не делает: узкие экраны проверяй замером
`document.documentElement.scrollWidth` в браузере, а не снимком.
