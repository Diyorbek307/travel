# HelloUZ Partner API

Стандарт, по которому любая система гостиницы или ресторана — OSHBOARD, iiko,
R-Keeper, своя разработка заведения — показывает в HelloUZ свободные места и
принимает брони туристов.

HelloUZ не пишет отдельный код под каждую систему. Система реализует три
адреса ниже, а заведение в панели HelloUZ включает режим «Система партнёра» и
вводит адрес, ключ и свой номер в этой системе. Всё.

Если системы у заведения нет, оно может отмечать свободные места в панели
вручную — режим «Вручную». Без подключения бронь уходит заявкой администратору.

---

## Как подключить

1. Система выдаёт заведению **ключ доступа** и сообщает **адрес API**,
   например `https://api.oshboard.uz/hellouz`.
2. В панели HelloUZ → «Гостиницы» или «Рестораны» → «Номера и наличие» /
   «Залы и наличие»:
   - режим — «Система партнёра»;
   - ID заведения в системе партнёра;
   - адрес API и ключ.
3. Кнопка «Проверить связь» спрашивает наличие на завтра и показывает ответ.

Ключ хранится на сервере HelloUZ и не попадает в приложение туриста.

## Общие правила

- Только HTTPS.
- Каждый запрос содержит заголовок `Authorization: Bearer <ключ>`.
- Ответы — JSON, кодировка UTF-8.
- На запрос наличия отвечать быстрее **4 секунд**, на бронь — быстрее
  **6 секунд**. Дольше HelloUZ не ждёт и показывает карточку без наличия.
- HelloUZ держит ответ о наличии **1 минуту**, поэтому одна и та же карточка
  не опрашивает систему чаще раза в минуту.
- HelloUZ передаёт только то, что нужно для брони. Система не должна
  передавать HelloUZ данные других гостей.

## 1. Наличие номеров в гостинице

```
GET {адрес}/v1/availability/hotel?external_id=…&checkin=2026-10-01&nights=2&guests=2
```

| Параметр      | Что это                         |
| ------------- | ------------------------------- |
| `external_id` | номер заведения в вашей системе |
| `checkin`     | дата заезда, `YYYY-MM-DD`       |
| `nights`      | ночей, 1–60                     |
| `guests`      | гостей, 1–30                    |

Ответ:

```json
{
  "rooms": [
    { "category": "standard", "free": 3, "price": 55 },
    { "category": "business", "free": 1, "price": 90 },
    { "category": "economy", "free": 0 }
  ]
}
```

- `category` — одна из: `economy`, `standard`, `business`, `lux`, `family`,
  `dorm` (место в общем номере хостела). Другие значения HelloUZ пропускает.
- `free` — сколько номеров этой категории свободно на все выбранные ночи.
- `price` — необязательно: цена за ночь в долларах на эти даты. Если не
  указана, турист видит цену из карточки HelloUZ.

## 2. Свободные столы в ресторане

```
GET {адрес}/v1/availability/restaurant?external_id=…&date=2026-10-01&time=19:00&guests=4
```

Ответ:

```json
{ "free_tables": 4, "next_free_time": "19:30" }
```

- `free_tables` — сколько столов на `guests` человек свободно на это время.
- `next_free_time` — необязательно: ближайшее время `HH:MM`, когда стол
  освободится, если сейчас свободных нет.

## 3. Бронь

```
POST {адрес}/v1/reservations
Idempotency-Key: <hellouz_booking_id>
```

```json
{
  "external_id": "…",
  "type": "hotel",
  "hellouz_booking_id": "b_…",
  "date": "2026-10-01",
  "time": "19:00",
  "nights": 2,
  "guests": 2,
  "room_category": "standard",
  "guest": { "name": "Anna Smith", "phone": "+49…", "email": "anna@…" },
  "note": "Поздний заезд"
}
```

- `time` — только у ресторана, `nights` и `room_category` — только у гостиницы.
- `Idempotency-Key`: при обрыве связи HelloUZ может повторить запрос —
  повтор с тем же ключом не должен создавать вторую бронь.

Ответ:

```json
{ "id": "ваш-номер-брони", "status": "confirmed" }
```

`status`:

- `confirmed` — место за туристом, он сразу видит «Бронь подтверждена»;
- `pending` — заведение подтвердит позже;
- `rejected` — мест нет, турист видит отказ.

Если система не ответила или ответила не по стандарту, бронь в HelloUZ
остаётся заявкой и её обрабатывает администратор HelloUZ.

## Для OSHBOARD

В OSHBOARD уже есть брони (`restaurants/:restaurantId/reservations`) и столы
(`restaurants/:restaurantId/tables`), но только для сотрудников, со входом.
Для HelloUZ нужен отдельный модуль с ключом заведения вместо входа
сотрудника, отдающий три адреса выше:

- наличие столов считается из столов и броней на выбранное время;
- бронь создаётся в тех же `reservations` с пометкой «из HelloUZ»;
- в настройках заведения — переключатель «Показывать свободные места в
  HelloUZ» и выдача ключа.
