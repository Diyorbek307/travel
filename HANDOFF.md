# Состояние проекта и что дальше

Документ для того, кто продолжит работу — человека или другого помощника.
Он не пересказывает код: код читается сам, а история коммитов объясняет
причины решений. Здесь только то, чего в коде не видно.

Дата среза: 26 августа 2026.

---

## Как запустить

```bash
npm install
npm run seed        # наполнить базу демо-контентом
npm run dev         # http://localhost:3000
npm test            # 68 проверок
npm run build       # сборка, как на хостинге
```

Развёрнуто: <https://uzbekistan-travel.onrender.com> (бесплатный тариф Render,
сервис засыпает после простоя — первый запрос идёт до минуты).

Пересборка данных, все скрипты идемпотентны:

```bash
node scripts/geo/build-context.mjs <папка-с-geojson>   # соседние страны
node scripts/geo/build-water.mjs   <папка-с-geojson>   # реки и озёра
python scripts/geo/build-relief.py                     # рельеф SRTM
node scripts/media/fetch-photos.mjs                    # снимки с Викисклада
```

## Известные ограничения

Это не недоделки по невнимательности, а осознанные размены. Прежде чем
«чинить», прочитайте причину.

**Счётчики помощника живут в памяти процесса** (`src/lib/ai-guard.ts`).
Потолок частоты и суточный кеш ответов — обычные словари. При одном
экземпляре на Render это работает; при нескольких у каждого будут свои
счётчики, и фактический потолок умножится на их число. Когда экземпляров
станет больше одного, сюда нужно принести общее хранилище.

**Цены и часы работы — правдоподобные, но не проверенные.** Их писал
помощник по общедоступным сведениям. Это **самый серьёзный риск проекта**:
турист, приехавший к закрытому музею, обвинит приложение и будет прав.
Нужны письма или звонки в администрации объектов.

**Тексты объектов — черновики.** Нужна вычитка историком.

**Аудиогиды — синтез речи.** Профессиональная запись загружается через
`/admin/audio` и автоматически заменяет синтез. ТЗ требует десять языков.

**Open-Meteo бесплатен только для некоммерческого использования.** Перед
запуском с монетизацией нужен их платный тариф.

**Хранение данных.** Render — Франкфурт. Закон Узбекистана требует
хранить персональные данные граждан внутри страны. Решать до запуска.

**Админка на одном пароле.** Нет ролей, нет журнала действий.

## Что делать дальше

По убыванию пользы. Первые три — не программирование.

1. **Сверить цены и часы** с администрациями объектов.
2. **Отдать тексты историку** на вычитку.
3. **Снять свои фотографии** двадцати главных объектов. Весь визуальный
   язык приложения держится на снимке; это изменит его сильнее любой вёрстки.
4. Роли и журнал в админ-панели — 2–3 дня.
5. Мониторинг ошибок: сейчас, если у туриста что-то сломается, мы не узнаем.
6. Фотографии в офлайн-пакет города.
7. Общий кеш и потолок частоты, когда экземпляров станет больше одного.

---

## Чего делать не нужно

Эти решения приняты сознательно, и их повторное «улучшение» сломает
работающее.

**Не подставлять фотографии объектам, у которых их нет.** Проверка
контактным листом уже поймала семь подмен: на «Ак-Сарае» была женщина
с флагом, на «Ляби-Хаузе» — ветеран с медалями. Пустая плашка честнее.

**Не давать языковой модели сочинять факты.** Цены, часы, координаты и
маршруты приходят только из инструментов, читающих базу (`src/lib/ai.ts`).
Модель, выдумавшая стоимость билета, отправит туриста к запертой двери.

**Не заменять детерминированный планировщик моделью.** Он покрыт тестами
и повторяем. Модель лишь решает, когда его позвать.

**Не убирать откат на разбор по правилам.** Офлайн-режим из ТЗ требует,
чтобы помощник отвечал без интернета.

**Не генерировать трёхмерные модели памятников нейросетью.** Получится
«похожее восточное здание», а не Регистан. Это та же подмена, что и
с фотографиями, только дороже.
