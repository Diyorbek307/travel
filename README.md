# UzRoam

Мобильное приложение-гид по Узбекистану: города, достопримечательности,
маршруты, отели, рестораны, транспорт, аудиогиды и AI-помощник. Работает
на десяти языках, с учётными записями туристов и админ-панелью для
редактирования содержимого.

Боевой стенд: https://uzbekistan-travel.onrender.com

## Быстрый старт

```bash
npm install
npm run dev
```

Откроется на http://localhost:3000. Никаких переменных окружения для
локального запуска не нужно — база и почта имеют запасные режимы (см.
ниже).

```bash
npm run build   # продакшн-сборка
npm test        # тесты (vitest)
npm run lint    # проверка стиля
```

## Как устроено

Клиентское приложение одностраничное: экраны переключаются состоянием
внутри макета телефона, а не маршрутами Next.js. Серверная часть — это
API-роуты (учётные записи, брони, отзывы, содержимое) и отдельная
админ-панель.

```
src/
  app/
    api/            серверные роуты: auth, content, bookings, reviews,
                    support, admin/*, health
    admin/          админ-панель (клиентское SPA за паролем)
    page.tsx        оболочка приложения
  components/
    screens/        вкладки: главная, исследовать, карта, аудио, профиль
    details.tsx     карточки места, отеля, ресторана, маршрута
    modals.tsx      поиск, уведомления, подписка
    *-provider.tsx  контекст: язык, контент, погода, валюта
  admin/            компоненты и контекст админ-панели
  data/             встроенное содержимое (семена) и типы
  lib/
    users.ts        учётные записи, пароли (scrypt), сессии
    storage.ts      хранилище: Postgres или файлы
    i18n.ts         словарь интерфейса на 10 языков
    content-i18n.ts перевод содержимого (описания, советы, ассистент)
    secrets.ts      обязательность секретов в бою
    rate-limit.ts   защита от перебора
    routing.ts      маршруты по дорогам (внешний движок)
```

## Данные и хранилище

Всё живёт за одним интерфейсом (`lib/storage.ts`) с двумя реализациями:

- **Postgres**, когда задан `DATABASE_URL`. Внешняя база переживает
  перезапуски и развёртывания — так работает боевой стенд.
- **Файлы** в каталоге `data/`, когда базы нет. Удобно для разработки.

На бесплатном тарифе Render у контейнера нет постоянного диска: без
`DATABASE_URL` учётные записи пропадают при каждом деплое. Проверить,
что база подхватилась, можно запросом `GET /api/health` — он отвечает
`"storage":"postgres","persists":true`, ничего секретного не раскрывая.

Встроенное содержимое (города, места, отели и т. д.) лежит в `src/data`
и служит первым кадром; правки из админ-панели приходят через
`/api/content` и заменяют его.

## Языки

Интерфейс переведён на десять языков (`lib/i18n.ts`), содержимое —
через словарь по исходной русской строке (`lib/content-i18n.ts`).
Топонимы (Регистан, Гур-э-Амир) намеренно не переводятся. Язык хранится
в `localStorage` и переключается в профиле; для арабского включается
режим справа-налево.

## Безопасность

- Пароли туристов — **scrypt** со случайной солью на каждого; в открытом
  виде не хранятся и наружу не отдаются.
- Cookie сессии и админки — подписанные, `httpOnly`, `secure` в бою.
- **Секреты обязательны в продакшене** (`lib/secrets.ts`): без
  `ADMIN_SECRET`/`SESSION_SECRET`/`ADMIN_PASSWORD` приложение не
  запускается уязвимым, а падает с понятной ошибкой. В разработке берутся
  запасные значения.
- **Защита от перебора** (`lib/rate-limit.ts`) на входе, регистрации,
  сбросе, подтверждении и админ-входе.
- **Заголовки безопасности** (`next.config.ts`): HSTS, защита от
  кликджекинга, `nosniff`, ограничение прав камеры и геолокации.

## Переменные окружения

Задаются в панели хостинга (на Render — Environment). В чат и в
репозиторий их класть нельзя.

| Переменная | Зачем | В бою |
|---|---|---|
| `DATABASE_URL` | Внешний Postgres. Без него данные не переживут перезапуск. | обязательно |
| `ADMIN_PASSWORD` | Пароль админ-панели. Без него в бою вход закрыт. | обязательно |
| `ADMIN_SECRET` | Подпись cookie админки. | обязательно |
| `SESSION_SECRET` | Подпись cookie сессии пользователя. | обязательно |
| `BREVO_API_KEY` или `SMTP_*` | Отправка писем (коды, сброс пароля). | по желанию |
| `MAIL_FROM` | Обратный адрес, например `UzRoam <noreply@uzroam.com>`. | по желанию |
| `ORS_API_KEY` или `OSRM_URL` | Маршруты по дорогам. Без ключа — прямая линия. | по желанию |
| `PAYME_MERCHANT_ID`, `CLICK_*` | Оплата подписки и броней. | по желанию |
| `NEXT_PUBLIC_GOOGLE_MAPS_KEY` | Встроенная карта Google. | по желанию |
| `DATA_DIR` | Каталог файлового хранилища (когда нет базы). | — |

Сгенерировать секреты:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Пока почта не подключена, коды подтверждения письмом не уходят — при
регистрации аккаунт подтверждается автоматически, чтобы вход не был
заблокирован.

## Админ-панель

`/admin`, вход по `ADMIN_PASSWORD`. В меню — разделы с настоящими данными:
брони, отзывы, чат, статистика, пользователи и всё содержимое (города,
места, отели, рестораны, события, туры, аудиогиды, реклама). Это общий
барьер, а не система ролей: у всех редакторов один пароль, журнала правок
нет — для крупной команды понадобятся отдельные учётные записи.

## Развёртывание

Render собирает и разворачивает при пуше в `main`. `NODE_ENV` в бою —
`production`, значит секреты из таблицы выше обязательны.

## Что ещё не сделано

- **Транспорт**: рейсы и поезда на экране — заглушки; кнопка «Купить» не
  ведёт на реальную покупку. Нужен переход на официальные сайты или
  партнёрский API.
- **Оплата**: интерфейс подписки и броней есть, платёжный провайдер не
  подключён (нужен `PAYME_MERCHANT_ID`).
- **Роли в админке**: единый пароль вместо учётных записей и журнала.
