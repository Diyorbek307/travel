# Uzbekistan Travel — единая туристическая платформа

Веб-платформа (PWA) и админ-панель по техническому заданию «Единая туристическая
платформа Узбекистана». Первая волна из трёх: веб делается первым и становится
источником API и контента для мобильных приложений.

> «Узбекистан без гида — ваш персональный гид всегда с вами»

Архитектура, схема данных, алгоритмы и дорожная карта — в [ARCHITECTURE.md](ARCHITECTURE.md).

---

## Запуск

```bash
npm install
```

```bash
npm run seed
```

```bash
npm run dev
```

Приложение — <http://localhost:3000>, админ-панель — <http://localhost:3000/admin>
(пароль по умолчанию `admin`, задаётся через `ADMIN_PASSWORD`, см. `.env.example`).

Продакшен-сборка:

```bash
npm run build && npm start
```

Офлайн-режим (Service Worker) намеренно отключён в режиме разработки — проверять
его нужно на собранной версии.

> **Не запускайте `npm run build`, пока работает `npm run dev`.** Оба пишут
> в каталог `.next`, и запущенный dev-сервер после этого начинает отдавать
> клиентские скрипты с ошибкой 404: страницы открываются, но карта и кнопки
> перестают работать. Если это произошло — остановите сервер, удалите `.next`
> и запустите заново.

## Развёртывание на Render

В репозитории лежит готовый blueprint [`render.yaml`](render.yaml) — Render
поднимет сервис по нему без ручной настройки.

1. Залейте репозиторий на GitHub:

```bash
git remote add origin https://github.com/ВАШ_АККАУНТ/uzbekistan-travel.git && git push -u origin main
```

2. В Render: **New → Blueprint**, выберите репозиторий. Render прочитает
   `render.yaml`, сам сгенерирует `ADMIN_PASSWORD` и `ADMIN_SECRET`
   (посмотреть их можно в разделе Environment сервиса).

3. После первого деплоя откройте `/admin/qr` — адрес сервиса подставится
   в QR-коды автоматически из `RENDER_EXTERNAL_URL`.

### Что важно знать про данные

Сервис по умолчанию поднимается на **бесплатном тарифе, у которого нет
постоянного диска**. Файловая система контейнера обнуляется при каждом
перезапуске и деплое:

- демо-контент восстанавливается сам — команда запуска наполняет пустую базу;
- **правки через админ-панель, загруженные аудиогиды и накопленная аналитика
  при перезапуске пропадут.**

Для демонстрации этого достаточно. Чтобы данные сохранялись, в `render.yaml`
нужно сменить `plan: free` на `plan: starter` и раскомментировать блоки
`disk` и `DATA_DIR` — оба сразу.

Бесплатный тариф ещё и засыпает после 15 минут без запросов: первый заход
после простоя занимает около минуты.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `ADMIN_PASSWORD` | Пароль админ-панели. Без него — `admin` |
| `ADMIN_SECRET` | Подпись сессионной cookie админки |
| `DATA_DIR` | Каталог базы и загруженных медиа. По умолчанию `./data` |
| `APP_BASE_URL` | Домен для QR-кодов. На Render берётся из `RENDER_EXTERNAL_URL` |

## Структура

```
src/
  lib/
    types.ts       доменные типы: категории, темы, языки
    schema.js      DDL — один источник правды для приложения и сидера
    db.ts          чтение данных
    admin-db.ts    запись данных (отдельно: страницы туриста не могут менять контент)
    planner.ts     алгоритм построения маршрута
    assistant.ts   разбор запросов на естественном языке
    geo.ts         расстояния, скорости, расписания
    i18n.ts        словари интерфейса
  app/
    (страницы туриста)
    admin/         админ-панель
    api/           REST для веба и будущих мобильных приложений
  components/
scripts/
  content/         демо-контент по городам
  seed.mjs         наполнение базы
```

## Данные

SQLite через встроенный в Node 24 модуль `node:sqlite` — без нативных сборок,
одинаково работает на Windows, Linux и в CI. Файл базы: `data/app.db`,
в репозиторий не попадает.

```bash
npm run seed
```

Пересоздаёт базу с нуля. Чтобы досыпать контент, не удаляя базу:

```bash
npm run seed -- --keep
```

Переезд на PostgreSQL + PostGIS затрагивает только `src/lib/db.ts`
и `src/lib/admin-db.ts` — наружу отдаются доменные типы, а не строки БД.

## Что нужно сделать до публичного запуска

Это демонстрационная версия. Технически она работает целиком, но к публикации
не готова по содержанию:

1. **Тексты историй — черновые.** Написаны по общедоступным сведениям и помечены
   в интерфейсе как требующие проверки. Перед публикацией каждый должен вычитать
   историк.
2. **Цены и часы работы** нужно подтвердить у дирекций объектов.
3. **Профессиональной озвучки нет.** Пока её нет, приложение читает тексты
   синтезом речи браузера и честно сообщает об этом. Реальные записи
   загружаются через `/admin/audio` и автоматически заменяют синтез.
4. **Фотографий нет.** Поле `poi_media.license` обязательно к заполнению:
   только собственная съёмка или CC-лицензии с указанием автора.
5. **Контакты посольств не заполнены** — вносятся из справочника МИД, а не
   приблизительно.
6. **Админ-панель защищена одним паролем.** Для продакшена нужны учётные записи
   редакторов, роли (администратор / контент-менеджер / музей) и журнал изменений.
7. **QR-таблички** требуют согласования с Агентством культурного наследия
   и дирекциями музеев. Перед печатью задайте `NEXT_PUBLIC_BASE_URL` — иначе
   коды уйдут в печать с адресом localhost.
8. **Персональные данные.** Аналитика обезличена by design, но при запуске
   регистрации потребуется политика конфиденциальности и учёт закона РУз
   «О персональных данных», включая локализацию хранения.

## Проверка

```bash
npx tsc --noEmit
```

Маршрутизатор удобно проверять через API:

```bash
curl -s -X POST http://localhost:3000/api/planner -H "content-type: application/json" -d '{"city":"samarkand","minutes":360,"themes":["history","architecture"],"budget":"medium","mode":"walk","lang":"ru"}'
```

AI-помощник:

```bash
curl -s -X POST http://localhost:3000/api/assistant -H "content-type: application/json" -d '{"text":"У меня 4 часа в Бухаре, люблю историю и хочу попробовать плов","lang":"ru"}'
```
